## 一、需求概述

### 1.1 现状分析

PatWiki 当前仅有专利-项目的硬编码关联（`PatentProjectLink` 模型），**无通用跨表关联字段类型**。飞书多维表格的 Link/Lookup/Rollup 是多维表格的灵魂功能，允许跨表引用和聚合计算。

### 1.2 目标

- 新增 `LINK` 字段类型：通用跨表记录引用
- 新增 `LOOKUP` 字段类型：从关联记录拉取字段值
- 新增 `ROLLUP` 字段类型：对关联记录做聚合计算（COUNT/SUM/AVG/MIN/MAX）
- 从专利-项目硬编码关联升级为通用 CrossTableLink 模型

### 1.3 专利场景示例

| 场景 | 字段类型 | 说明 |
|------|---------|------|
| 专利关联项目 | LINK | 选择关联的项目记录 |
| 拉取项目名称 | LOOKUP | 从关联项目拉取 name 字段 |
| 统计同族专利数 | ROLLUP | COUNT 关联的同族专利 |
| 汇总关联专利风险分 | ROLLUP | SUM 关联专利的 risk_score |

## 二、数据模型设计

### 2.1 CrossTableLink 模型（新增）

```python
# backend/app/models/cross_table_link.py（新文件）
class CrossTableLink(Base):
    # 通用跨表关联记录
    # source_table: 关联发起方表名（如 patents）
    # source_record_id: 关联发起方记录 ID
    # target_table: 关联目标方表名
    # target_record_id: 关联目标方记录 ID
    # link_field_key: 关联字段的 key（CustomField.key）
    __tablename__ = "cross_table_links"
    __table_args__ = (
        UniqueConstraint("link_field_key", "source_record_id", "target_record_id", name="uq_cross_link"),
    )
    id = Column(Integer, primary_key=True, index=True)
    link_field_key = Column(String(100), nullable=False, index=True)
    source_table = Column(String(50), nullable=False)
    source_record_id = Column(Integer, nullable=False, index=True)
    target_table = Column(String(50), nullable=False)
    target_record_id = Column(Integer, nullable=False, index=True)
    created_by = Column(String(100))
    created_at = Column(DateTime, server_default=func.now())
```

class RollupService:
    AGGREGATIONS = {
        "COUNT": lambda values: len(values),
        "SUM": lambda values: sum(v for v in values if v is not None),
        "AVG": lambda values: sum(v for v in values if v is not None) / len(values) if values else 0,
        "MIN": lambda values: min(v for v in values if v is not None) if values else None,

## 六、增量更新机制

1. 当 `CrossTableLink` 变更时，刷新关联该 link 的所有 Lookup/Rollup 字段
2. 当目标记录字段变更时，刷新引用该字段的 Lookup/Rollup
3. 与公式字段引擎共享 `DependencyGraph` 机制
