## 一、需求概述

### 1.1 现状分析

PatWiki 已有 `FILES_DIR` 配置目录用于存储文件，但**无附件字段类型**。飞书多维表格支持在单元格中上传和管理附件（PDF、图片、文档等）。专利管理场景中，需要存储专利证书 PDF、OA 通知书、对比文件等附件。

### 1.2 目标

- 新增 `ATTACHMENT` 字段类型
- 支持上传 PDF/图片/文档等文件
- 支持多文件管理（一个附件字段可存多个文件）
- 支持文件预览（PDF 内嵌预览、图片缩略图）
- 支持文件大小限制和类型限制

### 1.3 专利场景示例

| 场景 | 附件类型 | 说明 |
|------|---------|------|
| 专利证书 | PDF | 授权证书扫描件 |
| OA 通知书 | PDF | 审查意见通知书 |
| 对比文件 | PDF/图片 | 对比专利文件 |
| 申请材料 | PDF | 完整申请文件包 |
| 附件截图 | PNG/JPG | 补充说明截图 |

## 二、数据模型设计

### 2.1 CustomFieldType 扩展

```python
class CustomFieldType(str, enum.Enum):
    # ... 现有类型 ...
    ATTACHMENT = "attachment"
```

### 2.2 附件存储结构

附件文件存储在 `FILES_DIR/attachments/{database_id}/{patent_id}/` 目录下。

附件元数据存储在 `Patent.custom_fields` JSON 字段中：

```json
// custom_fields["cf_attachments"] 的值结构
[
    {
        "id": "att_001",
        "filename": "专利证书.pdf",
        "file_path": "attachments/1/42/att_001.pdf",
        "file_size": 1024000,
        "mime_type": "application/pdf",
        "uploaded_at": "2024-01-15T10:30:00",
        "uploaded_by": "user_001"
    }
]
```

### 2.3 Attachment 模型（可选独立模型）

```python
class Attachment(Base):
    __tablename__ = "attachments"
    id = Column(Integer, primary_key=True, index=True)
    database_id = Column(Integer, ForeignKey("patent_databases.id"), nullable=False, index=True)
    patent_id = Column(Integer, ForeignKey("patents.id"), nullable=False, index=True)
    field_key = Column(String(100), nullable=False, index=True)  # 关联的自定义字段 key
    filename = Column(String(255), nullable=False)
    file_path = Column(String(500), nullable=False)  # 相对路径
    file_size = Column(Integer)  # 字节
    mime_type = Column(String(100))
    uploaded_by = Column(String(100))
    uploaded_at = Column(DateTime, server_default=func.now())
```

## 四、API 设计

| 端点 | 方法 | 用途 |
|------|------|------|
| /api/attachments/upload | POST | 上传附件（multipart/form-data） |
| /api/attachments/{id} | DELETE | 删除附件 |
| /api/attachments/{id}/download | GET | 下载附件 |
| /api/attachments/{id}/preview | GET | 预览附件（PDF 内嵌/图片） |

## 六、文件存储安全

1. 文件名使用 UUID 重命名，防止路径遍历攻击
2. 文件路径不暴露真实路径，通过 API 下载
3. 上传时校验 MIME 类型（不仅检查扩展名）
4. 定期清理孤立文件（无 Attachment 记录的物理文件）
