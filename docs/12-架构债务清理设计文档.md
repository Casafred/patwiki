## 一、需求概述

### 1.1 现状分析

PatWiki 代码库存在以下架构债务：
- **前端路由未启用**：`react-router-dom` 已安装但未配置路由，所有导航通过状态切换
- **Service 层职责模糊**：部分业务逻辑直接写在 API 路由中
- **字段注册表硬编码**：`field_registry.py` 中系统字段定义硬编码，扩展性差
- **错误处理不统一**：各 API 端点错误处理方式不一致
- **缺少类型注解**：后端部分函数缺少类型标注
- **前端组件耦合**：部分组件直接调用 API 而非通过 Service 层

### 1.2 目标

- 启用前端路由系统（react-router-dom）
- 统一后端错误处理（全局异常处理器）
- 补全类型注解（Python + TypeScript）
- 重构字段注册表为可扩展架构
- 前端组件解耦（引入 API Service 层）
- 统一 API 响应格式

## 三、后端统一错误处理

### 3.1 现状

各 API 端点手动 try-catch，错误格式不一致。

### 3.2 目标架构

```python
# backend/app/core/exceptions.py（新文件）
class AppException(Exception):
    def __init__(self, code: str, message: str, status_code: int = 400):
        self.code = code
        self.message = message
        self.status_code = status_code

class NotFoundException(AppException):
    def __init__(self, resource: str, id: int):
        super().__init__("NOT_FOUND", f"{resource} {id} not found", 404)

class ValidationException(AppException):
    def __init__(self, message: str):
        super().__init__("VALIDATION_ERROR", message, 422)

class ConflictException(AppException):
    def __init__(self, message: str):
        super().__init__("CONFLICT", message, 409)

# backend/app/core/error_handler.py（新文件）
@app.exception_handler(AppException)
async def app_exception_handler(request, exc: AppException):
    return JSONResponse(
        status_code=exc.status_code,
        content={"code": exc.code, "message": exc.message, "detail": None}
    )

@app.exception_handler(Exception)
async def generic_exception_handler(request, exc):
    logger.error(f"Unhandled exception: {exc}", exc_info=True)
    return JSONResponse(
        status_code=500,
        content={"code": "INTERNAL_ERROR", "message": "Internal server error", "detail": str(exc)}
    )
```

### 3.3 统一响应格式

```python
# 所有 API 响应统一格式

    "code": "OK",           // OK / ERROR_CODE
    "message": "success",   // 描述

}

# 分页响应
{
    "code": "OK",
    "message": "success",
    "data": {
        "items": [...],
        "pagination": {
            "page": 1,
            "page_size": 20,
            "total": 47,
            "total_pages": 3
        }
    }
}
```

## 四、字段注册表重构

### 4.1 现状

```python
# field_registry.py — 硬编码系统字段
SYSTEM_FIELDS_REGISTRY = [
    {"key": "application_number", "label": "申请号", ...},
    {"key": "title", "label": "标题", ...},
    ...
]
```

### 4.2 目标架构

```python
# backend/app/services/field_registry.py（重构）
from abc import ABC, abstractmethod

class FieldHandler(ABC):
    # 字段处理器接口
    @abstractmethod
    def get_meta(self) -> dict: ...
    @abstractmethod
    def validate_value(self, value) -> Any: ...
    @abstractmethod
    def format_for_display(self, value) -> str: ...
    @abstractmethod
    def format_for_export(self, value) -> str: ...

class TextFieldHandler(FieldHandler): ...
class NumberFieldHandler(FieldHandler): ...
class DateFieldHandler(FieldHandler): ...
class SelectFieldHandler(FieldHandler): ...
class FormulaFieldHandler(FieldHandler): ...
class LinkFieldHandler(FieldHandler): ...
class AttachmentFieldHandler(FieldHandler): ...

class FieldRegistry:
    _handlers = {}  # field_type -> FieldHandler

    @classmethod
    def register(cls, field_type, handler):
        cls._handlers[field_type] = handler

    @classmethod
    def get_handler(cls, field_type) -> FieldHandler:
        return cls._handlers.get(field_type)

    @classmethod
    def get_all_field_types(cls) -> list:
        return list(cls._handlers.keys())
```

### 4.3 迁移步骤

1. 为每种字段类型创建 Handler 类
2. 将 `SYSTEM_FIELDS_REGISTRY` 迁移到 Handler 的 `get_meta()`
3. `get_all_fields_meta()` 改为遍历 Registry 中的所有 Handler
4. 新增字段类型只需注册新 Handler，无需修改现有代码

## 五、前端 Service 层引入

### 5.1 现状

前端组件直接调用 `fetch` / `axios`，URL 硬编码在组件中。

### 5.2 目标架构

```typescript
// frontend/src/services/api.ts
const API_BASE = "/api";

async function request<T>(method: string, path: string, body?: any): Promise<T> {
    const res = await fetch(`${API_BASE}${path}`, {
        method,
        headers: {"Content-Type": "application/json"},
        body: body ? JSON.stringify(body) : undefined,
    });
    const json = await res.json();
    if (json.code !== "OK") throw new Error(json.message);
    return json.data;
}

// frontend/src/services/patentService.ts
export const patentService = {
    list: (dbId: number, params?: any) => request("GET", `/patents?database_id=${dbId}&...`),
    get: (id: number) => request("GET", `/patents/${id}`),
    create: (data: any) => request("POST", "/patents", data),
    update: (id: number, data: any) => request("PUT", `/patents/${id}`, data),
    delete: (id: number) => request("DELETE", `/patents/${id}`),
};

// frontend/src/services/viewService.ts
export const viewService = { ... };

// frontend/src/services/formulaService.ts
export const formulaService = { ... };
```

### 5.3 迁移步骤

1. 创建 `services/` 目录和各 Service 文件
2. 将组件中的 `fetch` 调用替换为 Service 方法
3. 统一错误处理（Service 层抛出，组件层捕获并显示 Toast）
