# PatWiki 改造启动方案

> 状态：进行中
> 启动日期：2026-08-07
> 目标：在保持本地优先和专利垂直能力的前提下，建立接近飞书多维表格的基础产品架构。

## 一、基线结论

当前仓库已经具备：

- SQLite + FastAPI + React/Tauri 的本地优先运行架构。
- 专利库（Database）、Wiki 式增量导入、同族/引用关系解析。
- 主表 + 小表（Master + View）的后端模型、接口和字段来源追溯能力。
- 动态字段、内联编辑、筛选排序、批量 AI 任务和导出能力。

当前最明显的产品断点是：后端视图基础已经存在，但前端没有视图 API、视图切换入口和按视图加载数据的工作区闭环；另外原有 `view_type` 同时承担可见范围语义，无法直接扩展为表格/看板/表单/甘特类型。

## 二、第一批已启动改造

本批改造建立视图工作区基础契约：

1. 保留 `view_type` 作为个人/共享/部门总表的可见范围。
2. 新增 `layout_type`，支持 `table`、`kanban`、`form`、`gantt`、`calendar`。
3. 为视图预留分组、条件格式、看板、表单和甘特配置字段。
4. 前端新增视图列表、视图创建、当前视图状态和视图数据 API。
5. 专利列表接入当前视图查询；视图内编辑继续写入主表，并记录来源视图。

## 三、后续实施顺序

### 阶段 A：视图工作区闭环

- 已完成：保存视图筛选、排序、列显隐和列宽配置。
- 已完成：表格视图的分组与条件格式。
- 已完成基础闭环：看板视图按状态/选择字段分组，支持卡片字段配置和拖拽更新。
- 待完成：看板列排序、列内排序和大数据量虚拟滚动。
- 表单视图的字段布局、校验和提交。

### 阶段 B：多维字段能力

- 公式字段：安全 AST 解析、依赖图、增量重算和错误可见化。
- 通用关联字段：Link、Lookup、Rollup，替代专利-项目硬编码关联。
- 附件字段和导出字段选择。

### 阶段 C：协作与专利流程

- 评论、@提及、通知和操作历史。
- 自动化规则与期限提醒。
- 专利申请全生命周期、Docketing、费用与权限深化。

## 四、架构约束

- 主表是唯一事实来源，视图只保存查询、投影和视图本地字段。
- 专利数据默认不物理删除；库、视图和附件优先采用归档或软删除。
- 新能力通过服务层和配置模型扩展，不把业务规则堆入页面组件。
- 核心查询保持本地可用，云端 AI 只作为显式可选能力。
- 每个阶段都要有后端接口测试、前端类型检查和真实数据回归。

## 五、当前验收标准

- 切换库后只显示该库的视图和专利。
- 新建个人视图后可以立即切换并加载专利列表。
- 视图筛选和排序不破坏主表数据。
- 从视图编辑共享字段后，主表值和修改来源均可追溯。
- 旧的个人/共享/部门总表接口保持兼容。
