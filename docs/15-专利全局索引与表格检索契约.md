# PatWiki 专利全局索引与表格检索契约

> 状态：执行契约（2026-08-24）
> 读者：所有负责 PatWiki 代码、测试、迁移和 Agent 任务的开发 Agent。

## 1. 产品目标

PatWiki 的第一优先级是“以公开号锚定的全维度专利信息数据库”。今年不以专利事务全流程平台为目标。任何新功能都必须先回答：是否让检索、分析、撰写人员更快地存储、检索、核对、复用、导出一篇专利的完整信息？不能服务这个目标的功能降为后续阶段。

## 2. 全局身份原则

1. 一篇专利只能有一个 Wiki 实体。公开号是表格和文本跳转的首选识别标准；申请号、授权号是同一实体的补充身份，不得因为号码类型不同而复制一篇专利。
2. 公开号规范为 `国别字母 + 数字主体 + 文献类型字母 + 可选数字`，例如 `CN123456789A1`、`US1234567B2`。导入、手工编辑、关系解析、跳转解析都必须复用 `normalize_publication_number`。
3. 日本公开号的导出前导零必须去掉：`JP01234567A1` 归一为 `JP1234567A1`。来源原文不能丢弃，须留在导入来源行、观察记录或身份别名中。
4. 不能确认是规范公开号的值不得作为公开号身份写入正式字段；原始值必须作为待治理证据保留。
5. 同族、引用列只能存公开号列表原文和结构化关系，不得创建虚假业务记录。缺失目标在关系详情中显示 `missing_record`，主表不显示“待补全”占位记录。

## 3. 全局索引与库/视图

目标模型如下：

```text
CanonicalPatent / Patent
  ├─ PatentIdentifier（申请号、公开号、授权号及原始别名）
  ├─ PatentHistory / ImportSourceRow / FieldObservation
  └─ PatentScopeMembership
       ├─ 业务库 A
       ├─ 业务库 B
       └─ Saved View / 导出视图
```

当前代码已具备 `PatentIdentifier` 跨库唯一身份索引，且数据库唯一约束防止相同号码复制；`Patent.database_id` 仍是历史兼容的单库归属字段。因此当前实现是“全局身份索引 + 旧库归属兼容层”，还不是最终的 `PatentScopeMembership` 模型。

后续 Agent 实现正式成员关系迁移时必须遵守：

1. 先备份并建立迁移账本；为每个现有 `Patent.database_id` 生成成员关系，再切换查询，不得复制 Patent 行。
2. 导入到任一业务库时，先全局按规范公开号查身份；命中已有 Patent 时合并字段观察、历史和来源，并新增目标库成员关系。
3. 业务库、Saved View、导出模板都是过滤/投影，不拥有第二份专利正文。详情页、引用、同族、任意号码跳转始终打开同一个 Canonical Wiki。
4. 字段冲突按字段级处理：保留每个来源和时间，不允许“最新导入整行覆盖”。`最新且信息最多`必须由字段来源、采集时间、可信度和人工确认决定。
5. 在成员关系迁移完成前，任何涉及 `database_id` 的新代码都必须标记为兼容层，并同时评估跨库身份命中后目标库可见性。

## 4. 主表搜索与筛选契约

### 全局搜索

顶部搜索必须覆盖所有正式专利文本和 JSON 属性：公开号、申请号、授权号、标题、摘要、权利要求、说明书、申请人、发明人、专利权人、代理人、IPC/CPC、优先权、类别、技术问题/效果/方案、风险、模块、备注、`custom_fields`、`ai_fields`、项目名和标签。新正式字段加入时必须同步加入搜索字段清单，或者进入 JSON 搜索覆盖。

### 列筛选

每个列筛选是一个条件对象：

```json
{
  "publication_number": {"operator": "contains", "value": "CN2024"},
  "applicant": {"operator": "starts_with", "value": "某公司"},
  "notes": {"operator": "is_not_empty"}
}
```

允许操作符：`contains`、`eq`、`starts_with`、`ends_with`、`is_empty`、`is_not_empty`。多个列条件必须 AND；同一自定义字段在 `custom_fields` 与 `ai_fields` 中查找时，两者之间为 OR。旧版纯字符串筛选必须继续按 `contains` 解释。

筛选条件属于列表工作区状态，必须写入 URL，并在进入详情、返回、刷新、浏览器前进/后退、导出和工作文件生成时保留。清除只清除用户明确选择的列或全部筛选。

## 5. 单元格公开号跳转

任何表格单元格文本都要识别公开号。只有解析接口确认库中存在时才跳转到 Wiki；未知号码不创建占位记录，应给出未找到提示。识别必须允许一个文本中出现多个号码，非号码文本原样显示，点击号码不能触发行点击或编辑。

关系列、引用列、同族列、AI 输出列、自定义文本列、备注、权利要求等都适用此规则。前端正则只是候选识别，后端规范化和全库解析才是最终判断。

## 6. Agent 验收清单

每个涉及主表、导入、身份、关系或导出的任务完成前必须验证：

- 详情往返保留筛选、排序、分页、视图和搜索；
- 全局搜索命中 claims、description、custom、AI 和项目/标签；
- 六种列筛选操作符可用，多个字段为 AND；
- `JP0...` 归一化，原始来源仍可追溯；
- 关系缺失目标不出现在主表；
- 任意文本公开号可解析到同一 Wiki，不创建占位；
- 导入更新按字段保留来源和历史，不因缺标题/未知列丢弃整行；
- 运行后端定向测试、全量测试、`npm run lint`、`npx tsc -b`、`npm run build` 和 `git diff --check`。
