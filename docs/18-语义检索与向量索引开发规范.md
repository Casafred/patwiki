# PatWiki 语义检索与向量索引开发规范

> 状态：执行契约（2026-09-21）
> 适用范围：语义检索、Embedding、稀疏检索、混合召回、向量索引、Rerank、搜索评测及相关管理界面  
> 读者：所有负责 PatWiki 架构、代码、测试、迁移、打包和 Agent 任务的开发者  
> 当前阶段：Phase 1-3 核心能力已实现，Phase 4 的 `claims-description-v1` 全文分块已实现；下一阶段重点是实测基准、Windows 安装包回归和真实中文评测集沉淀

## 1. 文档地位与规范词

本文是 PatWiki 搜索体系的执行契约，与 `15-专利全局索引与表格检索契约.md`、`16-外部专利数据同步与监控架构规范.md`、`17-MCP统一适配与HimmPat集成开发规范.md` 同级。后续任何涉及语义搜索、向量化或重排的实现，都必须完整阅读并遵守本文。

- **必须**：验收门禁，不满足不得合并或发布。
- **应该**：默认做法；偏离时必须在设计或 PR 中说明原因、风险和替代验证。
- **可以**：按阶段和实际需求选用。

若旧文档或现有代码与本文冲突，以“SQLite 权威数据源、全局 Patent 身份、业务库/视图仅为作用域、权限不可绕过”为最高原则。本文不授权顺带重构无关模块。

## 2. 产品目标与非目标

### 2.1 产品目标

1. 用自然语言描述技术问题、方案或效果，找到语义相近专利。
2. 在精确号码、关键词、结构化条件和语义相关性之间形成稳定的混合排序。
3. 支持中文、英文及中英混合查询，并为结果提供可理解的命中片段和分数来源。
4. 支持可替换的 Embedding 和 Rerank 供应商，不将业务绑定到单一模型或向量引擎。
5. 在本地桌面环境中可运行、可降级、可重建、可审计，并控制网络调用成本。

### 2.2 非目标

第一阶段不建设独立分布式搜索集群、通用 RAG 问答或自动法律意见；不对说明书和权利要求做无上限切块；不用向量索引替代 SQLite、Patent 全局身份、字段筛选或权限；不把托管向量库设为唯一数据副本；不在保存专利的同步请求中调用 Embedding API。

## 3. 当前项目基线

截至本文建立时：

- SQLite 是权威业务数据源，`Patent` 及其身份、来源和历史不由向量库拥有。
- `settings.VECTORS_DIR` 已指向 `data/vectors`，并已建立按 profile/index version 隔离的可重建索引布局和生命周期实现。
- 当前搜索同时支持 SQL/FTS5 稀疏匹配、Dense Vector、RRF 和可选 Rerank，并保留轻量搜索建议接口。
- `Patent.search_vector` 是历史 `Text` 字段，不是数值向量；新实现不得用它保存向量或序列化数组。
- 已实现 OpenAI-compatible Embedding/Rerank Provider、Provider/Profile/Index/Job/Outbox/评测数据模型和完整 `/semantic-search` API；管理台已提供配置、健康检查、索引、任务、Case 和评测操作。
- 后台已有轻量轮询调度器，语义任务使用独立任务、租约、重试和 dead-letter 状态，不得塞入 Automation 或 Sync 的业务模型。
- SQLite FTS5 `trigram` 投影提供中文子串 BM25；不可用时自动回退 ILIKE，不影响主程序、CRUD 和关键词检索。
- 凭证只允许保存 `env://` 或 `keyring://` 引用，禁止保存明文密钥。

实现前必须通过迁移和兼容测试确认这些事实仍成立。

## 4. 核心架构原则

1. **SQLite 永远是事实源。** 向量索引只是可删除、可重建的检索投影。
2. **后端可替换。** 首选 Zvec 作为本地嵌入式 PoC 和首个实现，但服务层只能依赖 `VectorStore`；预留 Qdrant 等服务型后端。
3. **索引版本不可混写。** 模型、维度、距离函数、归一化、文本模板或分块策略任一变化，必须创建新索引版本。
4. **异步索引。** CRUD、导入、外部数据确认覆盖等写操作只写 outbox；模型调用和向量写入由后台任务执行。
5. **混合检索优先。** 默认同时使用精确身份、关键词/稀疏检索和 Dense Vector，并使用基于排名的融合。
6. **权限先于相关性。** 数据库、视图和用户权限必须在召回阶段约束，并在返回 SQLite 主记录前再次校验。
7. **精确号码受保护。** 公开号、申请号、授权号精确命中必须置顶，Rerank 不得将其降为普通语义结果。
8. **故障可降级。** Embedding、Rerank 或向量后端不可用时，关键词搜索仍必须可用，并返回降级状态。
9. **可解释且可评测。** 搜索应能说明 profile、索引版本、召回渠道、融合/重排分数和耗时。
10. **默认最小数据外发。** 仅向远程供应商发送必要文本，不发送附件、凭证、内部备注或未配置字段。

## 5. 技术选型与决策边界

| 能力 | 默认选择 | 边界 |
| --- | --- | --- |
| 权威数据 | SQLite + SQLAlchemy | 不变 |
| 本地向量/稀疏索引 | Zvec | 必须经 Windows PoC、版本锁定和打包验证 |
| Embedding | OpenAI-compatible Provider | 通过统一契约接入，不能散落 SDK 调用 |
| Rerank | 可选 Provider | 默认可关闭，失败时保留融合排序 |
| 融合 | Weighted RRF | 不混加 cosine、BM25、供应商分数 |
| 后台执行 | 现有生命周期 + 独立 Job/Lease | 不在 HTTP CRUD 内同步向量化 |

Zvec 的 GitHub 和官方文档声明支持嵌入式向量、Python、Windows x86_64 及向量/稀疏/混合能力，但声明不等于项目生产验收。引入前必须完成固定版本 PoC，验证索引创建、增删改查、并发打开、崩溃恢复、Windows 打包、中文 BM25 和数据量基准。

当单机规模、并发、内存或多设备共享需求超过实测边界时，可以新增 Qdrant 等后端。新增后端只能实现 `VectorStore`，不得要求上层修改查询语义；后端特有参数放入 profile 的受控配置。

## 6. 总体架构与数据流

```text
Patent CRUD / Excel Import / External Sync Confirm
                    |
                    v
         SemanticIndexOutbox (SQLite)
                    |
        SemanticJobService + Lease/Retry
                    |
                    v
  SemanticDocumentBuilder -> EmbeddingProvider
                    |               |
                    +-------> VectorStore
                                  |
Query -> scope/permission -> exact + keyword + dense recall
                                  |
                         RRF + optional Rerank
                                  |
                    SQLite rehydrate + permission recheck
                                  |
                     Patent rows + snippets + explain
```

### 6.1 写入链路

1. 业务事务更新 Patent、成员关系或可索引字段，并在同一事务写入去重 outbox。
2. 后台消费者领取事件，构建确定性文档并计算 `content_hash`。
3. hash 未变化则幂等跳过；变化后调用 Embedding，并写入目标索引。
4. 向量写成功后更新 `SemanticDocumentState`；失败可重试，不回滚业务数据。
5. 删除或失去作用域时写 delete 事件，索引删除成功后更新状态。

### 6.2 查询链路

```text
请求校验
-> 解析数据库/视图/用户作用域
-> 精确身份号码查询
-> 关键词/BM25 召回
-> Dense Vector 召回
-> 元数据与权限过滤
-> RRF 融合
-> 专利级 chunk 聚合与去重
-> 可选 Rerank
-> 精确命中固定置顶
-> SQLite 主记录回填和二次权限校验
-> 返回结果、解释与降级信息
```

任何优化都不得改变权限双检、精确命中置顶和 SQLite 回填。

```text
backend/app/search/

```

- `SemanticDocumentBuilder`：生成稳定文本、metadata、chunk 和 hash。
- `SemanticProviderRegistry`：构造 Provider，解析凭证引用并检查能力。
- `SemanticIndexService`：索引创建、增量、删除、校验、切换和重建。
- `SemanticSearchService`：作用域解析、召回编排、回填、降级和响应。
- `SearchFusionService`：RRF、去重、chunk 聚合、精确命中保护。
- `SemanticJobService`：outbox 消费、租约、批处理、重试和恢复。

API 层不得直接调用模型 SDK 或 Zvec；Provider 不得导入 SQLAlchemy；VectorStore 不得读取业务表。

## 8. 核心接口契约

### 8.1 Embedding Provider

```python
class EmbeddingProvider(Protocol):
    def capabilities(self) -> EmbeddingCapabilities: ...
    def healthcheck(self) -> ProviderHealth: ...
    def embed_documents(self, texts: list[str]) -> EmbeddingBatch: ...
    def embed_query(self, text: str) -> list[float]: ...
    def model_identity(self) -> ModelIdentity: ...
```

`model_identity` 必须返回 provider、model、dimensions、revision/endpoint identity。文档与查询向量维度必须严格一致；维度不符立即失败，不允许补零或截断。批量响应必须校验数量、顺序、空向量、NaN/Infinity。超时、限流、认证、输入过长和供应商故障转换为稳定错误码；只有可重试错误可指数退避重试。

### 8.2 Rerank Provider

```python
class RerankProvider(Protocol):
    def capabilities(self) -> RerankCapabilities: ...
    def healthcheck(self) -> ProviderHealth: ...
    def rerank(self, query: str, documents: list[RerankDocument], top_n: int) -> RerankResult: ...
    def model_identity(self) -> ModelIdentity: ...
```

Rerank 只接收已通过作用域和权限过滤的候选，只能改变这些候选的顺序。超时或错误回退至融合排序，不能导致整个搜索失败。

### 8.3 VectorStore

```python
class VectorStore(Protocol):
    def create_index(self, schema: VectorIndexSchema) -> IndexRef: ...
    def open_index(self, index_ref: IndexRef) -> None: ...
    def upsert(self, documents: list[VectorDocument]) -> UpsertResult: ...
    def delete(self, document_ids: list[str]) -> DeleteResult: ...
    def dense_search(self, query_vector, filters, limit): ...
    def sparse_search(self, query_text, filters, limit): ...
    def hybrid_search(self, query, query_vector, filters, limit): ...
    def count(self) -> int: ...
    def validate(self) -> ValidationResult: ...
    def close(self) -> None: ...
    def destroy(self) -> None: ...
```

`VectorDocument` 至少包含 `document_id`、`patent_id`、`document_type`、`chunk_index`、`text`、`vector`、`database_scope_ids`、`visibility`、`content_hash`、`index_version` 和受控 metadata。

`destroy()` 只能由索引生命周期服务调用，并必须确认目标位于 `VECTORS_DIR` 内、不是 active index、没有运行中任务且已记录操作日志。

## 9. 供应商配置与凭证安全

Embedding 和 Rerank 共用供应商管理框架，但能力分开声明。`provider_kind` 只允许 `embedding` 或 `rerank`。SQLite 只保存 endpoint、模型名、超时、批大小、并发、dimensions 等非敏感配置，及 `env://VARIABLE` 或 `keyring://service/account` 形式的 `credential_ref`。

严禁保存 API key、Authorization header、Cookie 或密钥解析值。日志、异常、搜索记录、任务样本、索引 metadata 和导出文件均不得出现密钥。

OpenAI 官方 Embeddings API 可作为首个实现。`text-embedding-3-small` 默认 1536 维，`text-embedding-3-large` 默认 3072 维，第三代模型可通过 `dimensions` 缩短向量。实际模型限制、token 上限和价格必须在部署/升级时依据官方资料复核，不得写成永久业务常量。profile 必须保存最终维度，创建索引前用受控探测验证响应维度。

## 10. 文档构建与分块策略

第一阶段每篇专利建立一个 `patent_summary` 文档，按固定模板组合：

```text
[TITLE]
标题
[ABSTRACT]
摘要
[APPLICANT]
申请人/专利权人
[INVENTOR]
发明人
[CLASSIFICATION]
IPC/CPC
[LEGAL_STATUS]
当前法律状态
[TECHNICAL_FIELDS]
技术问题、技术方案、技术效果、模块等允许字段
```

字段顺序、标签、空值处理、列表排序和文本规范化必须确定性一致。原业务字段不因向量化而改写。自定义字段和 AI 字段只有 profile 白名单中的字段可加入；内部备注、风险判断和敏感字段默认排除。`content_hash` 基于模板版本、规范化文本和相关 scope metadata 计算。

权利要求和说明书分块属于后续阶段。引入时必须按独立/从属权利要求、段落或章节做结构优先切分；保存类型、序号、起止位置和父专利；按模型 tokenizer 控制 token；限制重叠和单专利最大 chunk；策略变化必须更新 `chunk_strategy_version` 并建立新索引。

## 11. 索引身份、版本与磁盘布局

索引兼容身份至少由以下内容共同决定：

```text
backend_type
+ embedding provider/model/revision
+ dimensions
+ distance metric/normalization
+ document template version
+ chunk strategy version
+ sparse tokenizer/analyzer version
+ metadata schema version
```

任何一项变化都必须构建新索引。建议路径：

```text
data/vectors/<profile_id>/<index_version>/
  manifest.json
  index data owned by backend
```

`manifest.json` 不含凭证，至少记录 schema、模型身份、版本、创建时间、文档数、源数据水位、校验状态和应用版本。向量不得保存为 SQLite BLOB 或 `Patent.search_vector` 文本。

新版本采用 `staging -> validating -> active` 蓝绿切换：在 staging 全量构建；校验维度、数量、样本、作用域和评测；在 SQLite 事务中切换 active；旧版本标记 retired 并保留回滚期；无读取者和回滚需求后才能清理。

## 12. 数据模型

字段名可随 SQLAlchemy 规范微调，但语义不得弱化。

### 12.1 `SemanticProviderDefinition`

`id`、`name`、`provider_kind`、`provider_type`、`endpoint`、`credential_ref`、`config_json`、`enabled`、健康状态与时间、脱敏错误码、创建/更新时间。

### 12.2 `SemanticSearchProfile`

包含 backend、Embedding provider/model/dimensions、Rerank provider/model/enabled、retrieval mode、keyword/vector 权重、`rrf_k`、各阶段候选数、`rerank_top_n`、`result_top_k`、模板/分块版本、距离函数、索引字段和远程外发字段白名单。

影响索引兼容身份的字段不可原地改变；UI 应通过“克隆为新 profile/索引版本”变更。

### 12.3 `SemanticIndex`

包含 profile/database 作用域、index version、backend/path、`building | validating | active | retired | failed` 状态、active 标志、文档/专利数、源水位、manifest hash、各阶段时间和脱敏错误。同一 profile 与作用域最多一个 active index。

### 12.4 `SemanticIndexJob`

包含 `full | incremental | delete | rebuild | validate | activate` 类型、`pending | running | retry_wait | succeeded | failed | dead_letter | cancelled` 状态、进度统计、重试、下次执行时间、租约、checkpoint、错误和时间。租约过期由调度器回收；人工 retry 会重置本轮尝试窗口。

### 12.5 `SemanticDocumentState`

包含 profile、index version、patent、document type/ID、content/indexed hash、`pending | indexed | stale | deleted | failed` 状态、chunk 数、索引时间和错误。对 `(profile_id, index_version, document_id)` 建唯一约束。

### 12.6 `SemanticIndexOutbox`

包含 `upsert | delete`、patent、reason、来源事件、dedupe key、`pending | claimed | completed | retry_wait | dead_letter` 状态、重试、租约和时间。业务变更与 outbox 必须同事务提交；同一 Patent 连续更新允许合并为最新状态。

### 12.7 `SemanticSearchLog` 与反馈

日志至少记录 query hash、可选脱敏 query、scope、mode、profile/index version、候选数、结果数、降级原因、阶段耗时、模型 token/计费用量和错误码，默认不保存敏感查询全文。可选反馈表保存结果反馈用于离线评测，但不得直接在线自动改权重。

## 13. 增量索引、任务与恢复

以下入口必须产生 outbox：Patent 创建/更新/软删除/恢复；单元格与批量编辑；Excel/CSV 导入确认；外部专利数据确认覆盖；白名单内 AI/自定义字段变化；业务库成员关系、可见性或权限变化；索引字段配置变化。

不得依赖每个调用方手工触发，应在统一服务/事务边界封装并用集成测试覆盖。

- 文档 ID 确定性生成，如 `<patent_id>:<document_type>:<chunk_index>`。
- 相同 `content_hash` 已索引时跳过模型调用和 upsert。
- worker 使用有过期时间的租约，崩溃后任务可重领。
- 同一文档并发写按版本/序列号拒绝旧结果覆盖新结果。
- 批量 Embedding 部分失败只重试失败项，并维持输入输出映射。
- 超过重试上限进入 dead letter，可在管理界面查看和重试。

全量重建读取固定水位的 SQLite 快照/主键范围，期间新变化继续进入 outbox；完成基础构建后追平水位，再验证并激活。禁止清空 active 索引后原地重建。

## 14. 混合召回、融合、去重与重排

召回渠道包括：规范化公开号/申请号/授权号及别名的 Exact；标题、摘要、申请人、发明人、分类等 Keyword/Sparse；查询 Embedding 的 Dense；database/view membership、可见性、日期、申请人、IPC/CPC、法律状态等 Filter。

过滤应尽可能下推到召回；不能下推时过取候选再过滤，不得用过滤前数量冒充完整 top_k。

默认使用 Weighted Reciprocal Rank Fusion：

```text
score(d) = sum(weight_i / (rrf_k + rank_i(d)))
```

只融合名次，不直接相加 cosine、BM25 或供应商原始分数。权重和 `rrf_k` 属于 profile，修改后必须跑离线评测。

同一专利多个 chunk 先按 `patent_id` 聚合；每篇专利进入 Rerank 的 chunk 数设上限；最终列表按专利去重，返回最佳片段和少量补充片段，不能让长专利凭 chunk 数获得优势。

Rerank 只处理融合后的有限候选，并设置成本和超时。输入包含稳定 document ID 以校验响应；缺项、重复、越界或超时则整批回退 RRF。Rerank 后再次执行精确命中固定置顶。

## 15. 精确号码与权限保护

查询进入搜索前复用统一身份规范化。精确命中只针对后端确认存在的 `PatentIdentifier`，前端正则不能成为最终判断。排序为：当前作用域内完整规范号码精确命中、其他身份别名精确命中、混合结果；所有命中仍须通过权限和作用域。

第一道权限检查构建召回 filters，限制数据库成员、视图条件、可见性和用户权限。第二道按候选 `patent_id` 从 SQLite 批量回填时执行权威范围和权限查询。二次检查失败的结果直接丢弃并记录索引陈旧指标，不能向客户端或 Rerank 供应商泄漏无权记录的存在性、标题或片段。

## 16. API 契约

### 16.1 查询 API

`POST /api/semantic-search/query`

```json
{
  "query": "用于降低电池热失控传播的隔热结构",
  "database_id": 1,
  "view_id": null,
  "mode": "hybrid",
  "filters": {"legal_status": {"operator": "eq", "value": "active"}},
  "top_k": 20,
  "rerank": true,
  "profile_id": 1,
  "include_explain": false
}
```

query 去空白后不能为空；top_k、候选数和输入长度受服务端上限控制；客户端不能覆盖模型、endpoint、凭证或索引路径。

响应必须含 Patent 主记录、exact/keyword/vector/fusion/rerank 分数或名次、匹配片段、profile/index version、降级状态/原因和阶段耗时。`include_explain` 只对有权用户开放，不暴露其他记录、供应商原始响应、向量或密钥。

### 16.3 稳定错误码

至少包含 `SEMANTIC_PROFILE_NOT_FOUND`、`SEMANTIC_INDEX_NOT_READY`、`SEMANTIC_PROVIDER_DISABLED`、`SEMANTIC_PROVIDER_AUTH_FAILED`、`SEMANTIC_PROVIDER_RATE_LIMITED`、`SEMANTIC_PROVIDER_TIMEOUT`、`SEMANTIC_DIMENSION_MISMATCH`、`SEMANTIC_SCOPE_FORBIDDEN`、`SEMANTIC_QUERY_TOO_LONG`、`SEMANTIC_BACKEND_UNAVAILABLE`、`SEMANTIC_RERANK_DEGRADED`。

可降级错误返回成功响应加 `degraded=true`；没有关键词后备且无法执行时才返回业务错误。

## 17. 前端交互规范

- 列表搜索提供“关键词 / 语义 / 混合”分段模式，默认使用 profile 的混合模式。
- 输入、作用域、筛选、排序和模式写入 URL，可刷新、返回和分享工作区状态。
- 结果继续使用统一 Patent 行和详情，不建立第二套孤立详情页。
- 可展示“精确命中”“关键词”“语义”“已重排”等来源标记，详细解释按需展开。
- 降级时明确显示“语义服务暂不可用，当前显示关键词结果”等非阻塞状态。

管理界面已提供 Provider 健康/测试/启停、Profile 创建与受限编辑、active/staging 索引、任务重试、评测集 Case 维护、Recall/MRR/NDCG/Precision 指标和质量门禁。密钥只写入环境或系统 keyring，读取时永不回显。索引任务在后台继续，界面显示进度；激活前检查模型、维度、文档数、评测和回滚信息。

## 18. 降级、恢复、备份与迁移

降级顺序：Rerank 失败保留 RRF；Dense/查询 Embedding 失败保留 exact + keyword；稀疏后端失败回退现有 SQLite 关键词；索引未就绪或损坏时禁用 semantic 并提示重建，但主应用正常启动。

`zvec` 必须作为可选能力。依赖缺失、原生库加载失败或索引损坏时，主程序、CRUD、导入和关键词搜索仍可运行。

备份以 SQLite 业务数据和语义配置为核心。向量索引默认可重建；若备份索引，必须同时备份 manifest，并在恢复后校验应用版本、模型身份、维度和文件完整性。不得仅恢复索引而没有对应 SQLite 数据。

模型升级采用新 profile/版本、重建、离线评测、灰度验证、原子激活和回滚，禁止原地覆盖。

## 19. 性能、容量、成本与限流

实现前建立真实规模基准，至少覆盖 1 万、10 万及目标上限文档，记录索引大小、构建吞吐、查询 P50/P95、冷启动、内存峰值、批量删除和恢复时间。

- Embedding 批大小与并发可配置并受供应商限流。
- 查询 embedding 可按 `profile + normalized query` 做短期有界缓存，不跨模型复用。
- 文档 embedding 可由 `content_hash + model identity` 幂等复用，但不能绕过版本检查。
- Rerank 只处理有限候选，设置超时和单请求成本上限。
- 记录 token/调用量和估算成本；价格来自运行时配置或官方页面。
- 本地索引查询不得阻塞异步 API 事件循环，应使用受控线程池或异步适配。

性能目标必须基于实测，第一阶段以关键词基线无回归、混合查询 P95 可交互、后台索引不影响 CRUD 为验收方向。

## 20. 可观测性

结构化日志至少包含 request/job ID、profile/index version、provider/model、阶段、批大小、耗时、重试、错误码和降级原因。禁止记录凭证、完整向量、未脱敏响应和默认完整查询/正文。

指标至少包括：索引文档数、覆盖率、stale/pending/failed；outbox backlog 与最老事件年龄；任务成功/重试率；Embedding/Rerank 调用、token、限流和失败率；各渠道候选数、零结果率和降级率；各阶段 P50/P95；SQLite 二次校验淘汰数；每 profile 磁盘占用。

`/status` 区分配置、Provider、active index、覆盖率、积压和最近评测状态。Provider 健康检查不得每次搜索都执行。

## 21. 安全、隐私与合规

1. 远程 Embedding/Rerank 属于数据外发，管理界面必须明确 endpoint、字段白名单和供应商。
2. 默认只外发标题、摘要和公开著录字段；内部备注、风险意见、附件 OCR 和敏感自定义字段默认禁用。
3. Provider endpoint 必须校验协议和主机；自定义 HTTP endpoint 由部署安全策略控制。
4. 日志、分析和 fixture 使用脱敏或合成数据。
5. 查询和结果必须遵守用户、库和视图权限，语义相似不能成为越权理由。
6. 删除或权限收回应优先产生索引删除/metadata 更新事件并监控传播延迟。
7. 模型供应商的许可、数据保留和训练政策由部署方确认，代码不能默认假定。

## 22. 测试与离线评测

### 22.1 自动化测试

当前自动化测试必须覆盖：

- Provider 契约、错误映射、批次顺序、NaN/空向量和维度不匹配；
- VectorStore 创建、打开、upsert、delete、过滤、查询、validate、close；
- 全量、增量、删除、重建、校验、激活和回滚；
- hash 幂等、旧任务不覆盖新内容、租约过期和崩溃恢复；
- CRUD、批量编辑、导入、外部确认覆盖和成员关系变化产生 outbox；
- 数据库/视图范围、权限和 SQLite 二次校验；
- 精确号码优先，Rerank 无法降权；
- RRF、专利去重、chunk 上限和稳定排序；
- Provider 超时、限流、部分失败、Rerank 降级和关键词回退；
- Zvec 可选依赖缺失时主程序仍可启动；
- Windows 路径、原生依赖、PyInstaller/Tauri 打包和安装后目录；
- 迁移升级、旧配置、空库和损坏索引。

当前专项验收包括 18 项语义检索测试，完整后端测试 148 项；前端 `npm run lint`、`npx tsc -b`、`npm run build` 和 `git diff --check` 必须在提交前重新执行。质量门禁使用同一 Profile、同一 `index_version` 且状态为 `passed` 的评测运行；没有阈值时 `completed` 只表示执行完成，不等于通过。

外部 API 测试使用固定 fixture 或 mock，默认测试不得产生真实费用。

### 22.2 真实中文专利评测集

建立版本化人工标注集，至少覆盖精确号码、技术同义词和上下位概念、长自然语言、申请人 + 技术主题、中英跨语言、日期/法律状态/分类约束、否定/排除表达、低相关/无结果/歧义查询。

指标至少包括 `Recall@K`、`MRR`、`NDCG@K`、`Precision@K`、零结果率、P50/P95 延迟、Embedding/Rerank 调用量和成本，并与当前关键词基线对照。

模型、维度、模板、分块、融合权重、候选数或 Rerank 变化都必须运行评测。首批标注后确定最低门槛；门槛确定前新索引只能手动验收。质量显著下降、精确号码回归或权限失败时禁止激活。

## 23. 分阶段实施计划

### Phase 0：PoC 与基准

锁定 Zvec 候选版本，验证 Windows/Python/打包和核心操作；用合成及脱敏数据测 1 万/10 万规模；验证 OpenAI-compatible Embedding 的 dimensions、批处理和错误；建立评测集和关键词基线。

退出条件：PoC 报告、版本决策、容量数据和无明文凭证。

### Phase 1：基础设施与纯语义检索（已完成）

完成数据模型、迁移、Provider/VectorStore 契约、摘要文档、全量/增量任务、状态 API、Semantic 查询、SQLite 回填、权限双检和关键词降级。

退出条件：完整索引生命周期、崩溃恢复、可选依赖启动和后端测试通过。

### Phase 2：混合搜索与前端（已完成）

完成 Exact + keyword/BM25 + dense + RRF，列表模式、片段、解释、降级提示、URL 状态，以及 Provider/profile/index/job 管理。

退出条件：关键词基线无回归，混合评测和前端验收通过。

### Phase 3：Rerank 与生产门禁（核心已完成）

已完成 Rerank Provider、超时降级、非法响应回退、指标、离线质量阈值、staging index 评测和激活门禁。成本实测、真实数据集门槛和 Windows 安装包升级/回滚演练仍是发布前门禁。

### Phase 4：全文与扩展后端（全文分块已完成）

已完成权利要求/说明书结构化分块、稳定 chunk ID、旧摘要兼容和增量清理；按实测评估 Qdrant 等服务后端；在明确需求后评估 RAG，不与检索基础建设捆绑。

当前剩余工作是实测容量/延迟/成本、真实中文专利标注集、Windows 原生依赖和安装包回归，不得以“专项测试通过”替代这些发布门禁。

不得跳过 Phase 0 就把某引擎定为生产依赖，也不得在权限和降级未完成时先上线 Rerank。

## 24. 完成定义与验收门禁

- SQLite 仍是唯一业务事实源，索引可从零重建。
- Provider 与 VectorStore 抽象完整，业务服务无直接 SDK 依赖。
- 模型/维度/模板/分块/距离变化会生成新版本。
- 所有业务写入口可靠产生 outbox，增删改最终一致。
- exact、keyword、dense、RRF、去重和可选 Rerank 顺序符合契约。
- 精确号码优先和权限双检有回归测试。
- Provider/索引故障可降级，主程序和关键词搜索可用。
- 管理界面可看到配置、覆盖率、任务、错误、评测和 active 版本。
- 凭证、日志、远程字段白名单通过安全检查。
- 真实评测集不低于批准门槛，性能和成本有实测报告。
- 后端全量测试、前端 lint/TypeScript/build、迁移验证、Windows 打包相关验证和 `git diff --check` 通过。
- 文档、进度表和部署/回滚说明同步更新。

## 25. 明确禁止事项

- 禁止把向量或唯一索引状态写入 `Patent.search_vector`。
- 禁止将向量以 JSON/Text/BLOB 大量塞入 SQLite。
- 禁止在 API 路由、页面保存或单元格更新请求中同步调用 Embedding。
- 禁止业务服务直接 import Zvec/Qdrant/OpenAI SDK。
- 禁止同一索引混用不同模型、维度、模板、分块或距离函数。
- 禁止用向量索引替代权限、身份归一化或 SQLite 回填。
- 禁止让 Rerank 看到未授权候选或推翻精确号码保护。
- 禁止直接相加 cosine、BM25 和 Rerank 原始分数。
- 禁止在 SQLite、日志、fixture、索引 metadata 或前端保存明文密钥。
- 禁止索引不可用时阻止主应用启动或基本 CRUD。
- 禁止未经评测直接激活新模型/索引版本。
- 禁止依据 README 声明就认定第三方引擎已达到生产要求。

## 26. 后续扩展规则

新增模型供应商：实现 Provider 契约、离线 fixture、能力检查、错误映射和凭证引用，不修改搜索编排。  
新增向量后端：实现 VectorStore 契约和一致性测试，不修改 API 响应语义。  
新增文档类型：定义模板/分块版本、字段外发策略、chunk 聚合和评测集，不原地改变旧索引。  
新增检索策略：先在离线评测中与 RRF 基线比较，再通过 profile opt-in；不能绕过 exact 与权限阶段。
