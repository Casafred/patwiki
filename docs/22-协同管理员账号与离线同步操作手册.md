# PatWiki 协同管理员账号与离线同步操作手册

> 适用版本：离线文件同步阶段
> 目标读者：部门维护管理员、两位部门领导、各组组长

## 1. 先理解当前运行边界

每台电脑的 PatWiki 使用自己的 SQLite 数据库和协同账号目录。当前没有公司中央账号服务器，账号、组织、品类责任、同步授权和审计记录不会自动同步到其他电脑。

协同角色目前保护“部门协同 / 数据同步” API。它还没有接入专利主界面和一般业务 API，所以同一台电脑上能够运行 PatWiki、访问本机数据目录的人员，目前不能仅靠协同角色被隔离出本机专利数据。不要把当前版本当作全部门统一的数据访问控制或公司级身份认证系统。

离线试点应使用 IT 管理的电脑账户和受控的数据目录；不要让每位员工在自己的安装上自行初始化协同空间并担任管理员。每台参与收发的电脑都需要先由本机管理员完成协同空间初始化和账号预置。设备签名密钥放在操作系统凭据库中；设备指纹只能识别设备密钥，不能替代公司员工身份认证。

## 2. 角色与当前权限

| 角色 | 当前协同模块能力 |
|---|---|
| `system_admin` 维护管理员 | 管理本机协同账号、组织、责任、授权；不受同步授权范围限制 |
| `department_leader` 部门领导 | 与维护管理员相同，能管理本机协同配置并处理全部同步数据 |
| `group_leader` 组长 | 可登录和处理发给自己的包；导出或应用仍需明确授权；不能管理账号和授权 |
| `member` 组员 | 可登录、收取和查看授权范围内的包；导出或应用仍需明确授权 |
| `viewer` 只读协作者 | 可按导出授权生成或查看只读数据；不能获授或执行主表应用 |

角色名称不自动赋予组长全部品类权限。同品类跨组关系目前只记录协作关系，不会自动生成读写授权。

## 3. 初始化和管理员本人

1. 打开 PatWiki 的“设置 → 部门协同与数据同步”。
2. 首次启动时，按页面显示的完整路径读取 `setup-token.txt`。
   - 开发环境通常位于项目 `data/collaboration_sync/setup-token.txt`。
   - Windows 安装版通常位于 `%LOCALAPPDATA%\PatWiki\collaboration_sync\setup-token.txt`。
3. 输入初始化口令、管理员本人账号、显示名称和至少 10 位密码，点击“初始化并登录”。
4. 初始化账号自动成为 `system_admin`；系统会预建撰写组、检索组、分析组。
5. 安全保存管理员密码。初始化口令会在成功后删除，不能重复使用。

在每台电脑上执行初始化都会创建该台电脑的本地维护管理员。账号名相同不代表跨设备共享账号或可信身份。

首次登录后，在“可信同步设备”区域记录本机指纹和公钥。双方管理员应通过公司批准的独立渠道交换公钥，并逐字核对指纹，再在接收方设备登记发送方公钥。每台接收电脑都要单独登记。不要仅凭同一个网盘里收到的公钥和数据包建立信任。登记表会显示公钥对应的计算指纹，须与发送方确认的指纹完全一致。

## 4. 配置部门领导、组长和组员

使用维护管理员登录后，在“协同账号”区域逐一创建：

1. 两位总部门领导：角色选“部门领导”，不选择所属组。
2. 各组组长：角色选“组长”，并选择撰写组、检索组或分析组。一个组可以创建多位组长。
3. 普通同事：角色选“组员”，所属组选择其实际所在组。
4. 外部或临时只读人员：角色选“只读协作者”。

账号密码由管理员设置后，通过公司批准的密码渠道交给本人。员工第一次登录后，在面板顶部展开“修改协同密码”，输入初始密码并设置个人新密码；修改后其他登录会话会撤销，当前会话继续有效。停用离职或不再参与协同的账号；角色变更和停用只作用于当前电脑。

## 5. 配置产品品类责任

在“品类责任”区域，对每项责任单独保存：

1. 选择同事、工作组和组内小组。
2. 选择产品品类。
3. 选择“主要负责人”“备份负责人”或“复核人”。
4. 点击“保存品类责任”。

同一同事可重复添加多项不同品类责任。同一品类的撰写、检索、分析人员会形成协作关系记录，但该记录不是同步授权。

## 6. 授予导出和主表应用权限

“同步导出授权”区域创建的是本机显式授权，按用户、数据库、品类、字段、动作和 90 天有效期限制。

1. 选择目标同事和本机数据库。
2. 选择一个或多个品类；不选品类表示该数据库的全部品类。
3. 在生成共享包之前，按允许范围选择字段。标题是必选字段。
4. 只允许发出文件时选“导出”。
5. 允许接收并写入本地主表时，再选“应用到本地主表”，设置至少 10 位的独立编辑密码。
6. 创建授权后，可在授权列表中撤销。

导出授权应由数据拥有方或部门领导配置。主表应用授权应在接收电脑配置，因为授权数据库和用户都属于接收电脑的本地目录。编辑密码应通过与 `.pwshare` 不同的批准渠道传递。部门领导和维护管理员可直接应用，不需要单独的 `apply` grant。

## 7. 发出和接收一个共享包

### 发出方

1. 登录 PatWiki 协同账号，打开“生成加密共享文件”。
2. 选择一个数据库、需要共享的品类、字段和接收人的协同登录名。
3. 设置至少 10 位共享密码；通过单独渠道通知接收人。
4. 点击“核对导出范围”，确认数量和字段后生成 `.pwshare`。
5. 把文件放入公司批准的网盘位置或按内部流程传递。

当前包是加密全量快照，每包最多 20,000 条记录、100 MB；暂不包含附件二进制、评论、同族/引用关系和组织权限配置。导出时附件字段中的本机路径和下载地址会被排除。

未登记设备签发的有效 v2 包和旧版未签名 v1 包可以保存到只读共享区，但不能应用到本地主表。已经生成的 v1 文件不会自动升级签名；若先导入 v2 包后才登记发送设备，可再次预览并应用；系统会在应用时重新检查设备是否仍受信。

### 接收方

1. 接收电脑需预先有与包接收人名单完全一致的协同登录名；否则由本机管理员先创建账号。发送设备还必须已登记为本机可信设备，才能应用到主表。
2. 登录接收账号，选择 `.pwshare` 并输入共享密码，点击“解密并预览”。预览会标记签名可信、签名待登记或未签名。
3. 确认发送者显示信息、记录范围和样例后，点击“导入到只读共享区”。这一步不会改动主表。
4. 若需要写入本地主表，先确认该接收账号在本机有匹配数据库、品类和字段的 `apply` 授权，并取得独立编辑密码。
5. 点击包的“预览主表应用”，选择本机目标数据库；查看新增、更新和冲突。
6. 对每个冲突字段选择“保留本机”或“接受接收值”，然后执行应用。
7. 应用成功后检查包状态和专利历史。同步前 SQLite 备份保存在数据库文件旁的 `backups/collaboration-sync/`。

来源记录的申请号、公开号或授权号若在接收电脑已对应其他 UID，系统会匹配到本机现有专利，避免创建重复件；号码命中多条记录或命中已删除记录时会阻止应用，需先人工处理。

## 8. 推荐的账号配置例子

假设维护管理员为 `patwiki-admin`，两位部门领导为 `leader-a`、`leader-b`，撰写组长为 `write-lead-1` 和 `write-lead-2`，撰写同事为 `writer-x`：

1. `patwiki-admin` 完成首次初始化，成为 `system_admin`。
2. 创建 `leader-a`、`leader-b`，角色均选 `department_leader`。
3. 创建两位撰写组长，角色选 `group_leader`，所属组均选“撰写组”。
4. 创建 `writer-x`，角色选 `member`，所属组选“撰写组”。
5. 在品类责任中，分别给每位组长和 `writer-x` 分配其负责的品类；例如组长甲负责 X、Y，组长乙负责 Z，`writer-x` 负责 X。
6. 如需 `writer-x` 向检索同事共享 X 品类，管理员在发出方电脑给 `writer-x` 创建 X 品类的 `export` 授权；若接收方要写入主表，再由接收方电脑管理员给其创建 X 品类的 `apply` 授权和独立编辑密码。
7. 对另外两台电脑分别完成本地初始化和对应账号预置。若该包接收人是 `retriever-b`，接收电脑必须用本机管理员预先创建完全同名的 `retriever-b` 账号。

## 9. 尚未完成的协同阶段

1. **增量和检查点**：目前重复交换完整快照，尚无接收确认后安全推进的增量游标和回传包。
2. **删除同步**：PatWiki 现有删除流程会物理删除记录；稳定 tombstone 需要先统一删除/恢复生命周期。
3. **附件同步**：需要按 SHA-256 内容寻址、包内加密、病毒扫描/类型校验和独立附件授权。
4. **发送者真实性**：已完成 Ed25519 v2 包签名、操作系统凭据库存钥、可信设备登记和撤销；管理员需逐台核对指纹。签名只证明设备密钥，设备上的员工身份仍由本地账号记录，未接入公司身份服务。
5. **组织配置分发**：目前需逐台维护账号、角色、品类责任和 grant；需管理员专用配置包或中央身份/配置服务。
6. **协作关系到授权策略**：同品类关系尚不会自动授予只读或编辑权限；映射必须由部门确认，不能默认把关系升级为写权限。
7. **LAN/中继和实时协作**：需要公司 IT 提供认证、审计、备份和服务端存储后再启用，不能让多台电脑直接共用 SQLite 文件。

优先顺序建议：先完成双电脑端到端验收和受控组织配置分发；接着完成增量/检查点、删除生命周期和附件同步；最后接入 LAN/中继。统一数据可见性和真正的数据权限需与公司身份服务、服务端授权及现有业务 API 一起完成。
