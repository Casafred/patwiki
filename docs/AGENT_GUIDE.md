## 🎯 Agent 开发标准流程

每次接到开发任务时，按以下步骤执行：

### Step 1: 理解上下文
```
1. 读取 00-总体项目规划文档.md → 理解项目定位
2. 读取 DEVELOPMENT_PROGRESS.md → 了解当前开发进度
3. 读取 00-MVP范围与优先级.md → 确认任务优先级
```

### Step 2: 获取规范
```
4. 读取 03-项目结构与代码规范.md → 掌握编码规范
5. 读取 05-AI开发规范.md → 遵循 AI 编码规则
```

### Step 3: 定位参考文档
根据任务类型，查阅对应编号的设计文档：

| 任务类型 | 需查阅的文档 |
|----------|-------------|
| 新增数据模型/字段 | `04-专利业务模型设计.md` + `02-关联字段体系设计文档.md` |
| 开发视图组件 | 对应编号的视图设计文档（04-看板 / 05-表单 / 07-甘特 等） |
| 实现核心 CRUD/导入 | `07-P0阶段-库模型与Wiki式导入设计.md` |
| 添加公式/计算 | `01-公式字段引擎设计文档.md` |
| 导出功能 | `03-数据导出功能设计文档.md` |
| 自动化/规则 | `08-自动化规则引擎设计文档.md` |
| 重构/清理债务 | `12-架构债务清理设计文档.md` |
| 风险评估 | `01-项目风险与遗漏分析.md` |

### Step 4: 编码与验证
```
6. 按文档规范编码，保持与现有代码风格一致
7. 完成后更新 DEVELOPMENT_PROGRESS.md
8. 运行测试确认无误后提交
```

## 📝 文档维护规则

### 新增文档
- 使用两位数字编号开头，如 `14-xxx设计文档.md`
- 编号按文档主题分类，而非创建时间
- 必须包含：目标、设计思路、接口定义、数据模型（如适用）

### 更新文档
- 改动较大时，在文档顶部标注 `[已更新: YYYY-MM-DD]`
- 涉及架构变更时，同步更新 `02-轻量化架构设计.md`
- 涉及模型变更时，同步更新 `04-专利业务模型设计.md`

### 提交规范
- 文档变更单独提交，commit message 格式：`docs: 更新 xxx 设计文档`
- 代码和文档分开提交，便于 review

## ❓ 遇到不确定时

1. **先读文档** — 所有设计决策都有文档记录
2. **再看代码** — 参考 `backend/app/services/` 和 `frontend/src/components/` 下的现有实现
3. **最后提问** — 若文档和代码都无法解答，向用户确认
