# 25 - PatWiki Agent 开发协议

> 状态：`agent-executable / mandatory`
> 更新：2026-08-17
> 本文面向执行开发任务的 Agent，不是给人阅读的背景介绍。Agent 开始任何代码、数据库、导入、详情页、表格、导出或交互改动前，必须按本文执行。

## 1. Agent 的唯一当前任务目标

PatWiki 当前不是全面 IP 工作流平台。Agent 的首要目标是交付：

**以每篇专利为锚点、可随手录入和持续积累、可完整查询调用、可追溯、可生成 Excel/Word 工作文件的本地交互数据库。**

当前默认运行边界：单人、本地、Tauri + React/Vite + FastAPI + SQLAlchemy + SQLite。除非用户明确改变范围，Agent 不得主动引入云端、跨设备、多人权限、ERP/PLM/代理系统集成或完整 Docket 工作流。

## 3. 标准任务循环

每次任务按以下顺序执行，并在最终报告中逐项说明：

1. **分类范围**：判断属于 P0 专利信息中心、P1 专利关联能力，还是长期延后能力；主动排除超出范围的部分。
2. **读取规范**：完成 2.1 和 2.2 的文档读取，记录实际采用的章节。
3. **检查代码事实**：定位现有模型、服务、API、页面、迁移和测试；不得假设文档所述能力已经实现。
4. **定义数据路径**：写明输入、身份、字段状态、来源观察、当前采用值、审计和失败处理；未知属性必须遵守 `unmapped_retained` 规则。
5. **先补规则再写代码**：若交互、字段语义、状态或数据关系在文档中没有定义，先更新权威 Markdown/CSV，再实现。
6. **最小闭环实现**：模型/迁移、服务、API、前端、导入/导出和测试必须形成可用闭环；不能只做空 UI 或只做表结构。
7. **按场景验证**：至少覆盖正常路径、重复导入、空值/部分录入、冲突、撤销/恢复、来源追溯和未知属性路径。
8. **复核范围**：检查是否误覆盖人工数据、是否把草稿当正式结论、是否增加了不必要的复杂工作流。
9. **交付报告**：说明改动文件、文档依据、测试命令与结果、未完成项和需要用户确认的问题。

### 3.1 当前 G0 任务执行要求

涉及未知属性、导入治理或来源追溯时，Agent 必须先检查 `DEVELOPMENT_PROGRESS.md` 的 G0 状态和 `21-implementation-contract.md` 的 4.0 节。实现顺序固定为：

1. 先完成服务层决策和事务边界；
2. 再补 API schema、回归测试和导出；
3. 最后实现工作台，不允许只做页面状态而绕过服务层；
4. 每次将未知属性升级为正式字段前，必须明确字段名称、类型、责任人、来源范围和统计口径；缺一项只能保留为来源专用字段或候选字段。

Agent 不得以“用户已经看到 CSV”为理由跳过确认、回填、历史和失败重试。当前 G0-8 已提供四类治理动作、分页、逐观察决策历史和可恢复治理批次；统一专利身份、六类高频业务视图和 Excel/Word 模板仍属于 G0-7，不能在交付报告中提前声称完成。

### 3.2 当前治理接口执行清单

当任务涉及待治理属性时，Agent 必须按以下顺序实现和验证：

1. 队列读取使用 `GET /import/unmapped`，默认状态是 `unmapped_retained`；完整来源审计使用 `GET /import/unmapped/export`，默认状态是 `all`，不得把完整导出误当成待处理队列。
2. 决策只能通过 `PATCH /import/observations/{observation_id}`；前端不得直接写 `Patent`、`Patent.custom_fields`、`FieldObservation` 或自行伪造历史。
3. 批量动作必须将影响范围固化为 `ImportBatch + source_field_name`，响应返回 `updated_count` 和 `adopted_value_count`，前端明确展示这两个数字。
4. 对 `map_existing` 同时验证 Field Registry、采用来源值开关、空值不覆盖和 `PatentHistory(source=governance)`；对 `retain_source`/`ignore` 验证观察记录仍存在并能在 `status=all` 导出中出现。
5. 每次新动作至少增加：单条路径、批量边界路径、原始证据保留路径、决策历史路径和失败重试路径测试；没有这些测试不能标记完成。

6. 实现恢复时必须保存并校验决策批次的变更前状态。恢复只能新增 `GovernanceReversal` 和 `PatentHistory(source=governance_revert)`；若发现观察有后续决策或专利字段已被修改，必须返回可操作错误，不得增加强制覆盖开关。

## 4. 不可违反的开发规则

涉及项目方案版本或风险跟踪时，必须额外阅读并遵守 `27-agent-project-risk-module-contract.md`。该文件优先解释本模块的草稿/正式结论门禁、兼容风险投影和当前未实现的 Artifact 边界。

- 未知列、未知属性或暂时无法归类的信息不能静默丢弃，不能未经治理写入正式字段、默认统计或 `Patent.custom_fields`。
- 可解析且身份可保留的输入进入 `unmapped_retained`；只有损坏、解析失败、身份冲突或完整性错误进入 `quarantined`。
- 外部导入不能静默覆盖人工分类、分析、风险、保护和内部关系；空单元格默认表示“不修改”，不是清空。
- 来源观察、候选规范值和当前采用值必须分离；相同值也必须记录来源观察。
- 专利申请号、公开号和授权号必须按身份规则归并；同族成员只关联不合并。
- 专利关系必须先读取 `24` 的 4.5 节：正式关系键为 `family_members`、`cited_patents`、`citing_patents`。导入关系列时必须双轨保存原始单元格文本和结构化关系实体；原始列不能被关系 ID 替代，关系实体也不能被逗号文本替代。
- `cited_patents` 的方向是当前专利 -> 被引用专利，`citing_patents` 的方向是引用专利 -> 当前专利。详情页必须分开展示“我引用的专利”和“引用我的专利”。
- 关系读模型必须明确 `in_database`、`other_database`、`missing_record` 三种状态。当前库目标可导航，其他库目标只能标注，未入库目标保留号码但不能伪造详情链接；读取关系不得创建占位专利。
- 同族关系必须具备可导航读模型：详情页成员清单和关系图节点都要能打开目标专利详情；同族聚拢只能是当前数据库/视图范围内的展示投影，不能复制、合并或跨库泄漏 Patent 记录。
- 多值关系不能用逗号文本、JSON ID 数组或页面临时字段代替关系实体。关系原始投影是只读字段，普通单元格、详情编辑、批量更新和普通创建接口不得改写；只有导入来源流程或明确的关系服务可以写入。
- 正式风险、正式决策和人工确认值不能由 AI 或前端直接签发；必须经过服务层校验和审计。
- `ProjectSolutionVersion` 已确认后只能通过新版本修订；`RiskAssessmentVersion` 和 `RiskReviewEvent` 只能追加，不能用 PUT/DELETE 覆盖历史。
- 正式风险评估必须具备具体方案版本、法域、分析人、确认人、决定时间和服务端 `input_hash`；不完整内容只能保存为草稿。
- `Patent.has_risk/risk_level/risk_description` 是兼容读取投影，禁止从详情、单元格、批量或外部导入写入。
- 迁移不能继续依赖吞异常的容错加列；复杂拆分、回填和索引必须进入版本化迁移和备份门禁。
- 不得为了“方便”把所有业务对象塞进专利表或自定义字段；字段位置必须有 Field Registry 依据。
- 不得用大规模重写 UI、重命名主表或引入长期平台能力阻塞专利信息中心。

## 5. Agent 交付完成定义

### 5.1 数据完整性

- 任一新增值都能追溯到操作者/批次、时间、来源和原始值；
- 用户只录入部分信息时可以保存草稿，后续可以继续编辑；
- 空值不会意外清空已有值；批量修改有范围、预览、审计和撤销/恢复路径；
- 未知属性可查询和导出，后续映射不会删除原始观察；
- 重复导入幂等，身份冲突和内容冲突不会静默合并。

### 5.2 交互可用性

- 高频录入不要求用户先完成复杂主数据配置；
- 已知专利可以从详情页直接编辑，未知专利可以先进入待补身份 Inbox；
- 可用键盘完成新增、保存、取消、下一项、复制和批量粘贴；
- 用户能明确看到“已保存/草稿/冲突/待治理/失败”，不能只依赖 Toast 或颜色；
- 录入失败时保留输入并提供修正后重试，不要求重新输入整行。

### 5.3 工程验证

- 运行与改动相关的后端、前端、迁移和导入测试；
- 新增业务规则必须有自动化测试或可重复验收脚本；
- 执行 `git diff --check`；
- 文档、CSV、Schema 与代码引用保持一致；
- 最终报告列出未运行的测试和剩余风险，不得声称未验证的能力已完成。

## 6. 需要暂停并请求确认的情况

Agent 只有在下列情况暂停请求用户确认：

- 删除或不可逆覆盖真实数据；
- 业务规则会改变正式风险、保护、分类或统计含义；
- 需要把未知属性直接升级为正式字段，但语义、责任人或统计口径不明确；
- 需要引入云端、跨设备、多人权限、外部系统连接等超出当前边界的能力；
- 现有用户改动与任务发生实质冲突，无法在不丢失改动的前提下继续。

普通字段缺失、来源未知或数据不完整不构成暂停理由：应按草稿、来源观察或 `unmapped_retained` 路径继续保留。

## 6.1 G0-7 Agent 强制规则：身份、视图和输出

- 处理任何专利号前先调用 `patent_identity_service`；禁止在 API、组件或导入循环中自行写一套去空格/去后缀规则。
- `find_patents_by_identifiers()` 返回多个 Patent 时只能进入 `identity_conflict/quarantined`；禁止选择第一条、按标题猜测或把同族当成合并依据。
- 新建或修改 Patent 的号码字段后必须执行身份索引同步；测试必须覆盖申请号、公开号、授权号同链、格式别名和跨记录冲突。
- 视图只能保存字段投影/筛选/排序/分组；高频业务需求先复用 `PatentView`，不得复制 Patent 行或把业务表再建成主数据表。
- 导出模板只能保存配置和版本；所有导出都从当前主表/视图重新查询。Excel/Word 输出必须带模板版本、筛选条件和字段来源，测试必须验证这些血缘信息存在。
- Agent 修改 `PatentIdentifier`、高频视图 key、模板字段或导入状态时，必须同步 21 号契约、开发进度和自动化测试；不能只改前端类型或页面。
- Agent 修改高频视图字段时必须使用 `PatentView.column_config` 和 `PUT /views/{view_id}`：不得只写 `localStorage`，不得把字段显隐、顺序或列宽写入 `Patent`。
- 非空 `column_config` 中只有 `visible=true` 的已注册字段可以进入表格；配置缺少的新字段默认隐藏但必须能在列管理中主动加入。未知 key 必须保留，不能因为当前字段注册表不认识就丢弃。
- 列管理交互至少覆盖搜索、显隐、上下移动、宽度、全部显示/隐藏、恢复初始、取消、保存成功/失败和重试；表头拖动列宽也必须最终持久化到当前视图。
- 视图列配置不能改变 `PatentExportTemplate.field_keys`。导出模板和当前视图是两个配置边界，除非任务明确实现“从当前视图创建模板”。
- 视图列任务必须增加 API 回归：配置重读、视图隔离、未知 key、重复 key 拒绝、主数据不变，以及前端刷新后的配置恢复；未覆盖这些场景不得标记完成。

### 6.2 关系导入与读取强制门禁

- 任何包含同族/引用列的导入，必须先保存完整 `ImportSourceRow` 与 `FieldObservation`，再调用关系解析；关系解析失败不能回滚或删除原始来源证据。
- 关系号码使用 `patent_identity_service` 匹配；已有目标建立幂等关系，缺失目标默认不建占位并在读模型返回 `missing_record`；禁止以标题、同族或列表顺序猜测目标。
- 关系导入返回的 `family_links`/`citation_links` 只统计真实建立或复用的结构化关系，不得用解析到的号码数量冒充成功关系数。
- 关系 API、图谱、列表聚拢必须绑定根专利的 `database_id`。跨库记录不能进入当前库默认图谱或聚拢，但可以在详情关系清单中标记 `other_database`。
- 导出选中 `family_members`、`cited_patents`、`citing_patents` 时必须输出关系原始投影文本；不得导出关系实体 ID 取代来源列。
- 新增关系行为至少测试：多值分隔符、正反方向、重复导入幂等、当前库/其他库/未入库状态、读取无副作用、原始列导出和普通编辑拒绝。

### 6.3 主表批量命令与工作台交互门禁

- 主表多选操作必须使用服务层批量命令，禁止前端循环调用单条更新接口伪装成批量操作。命令至少返回成功数量、目标标识和可读失败原因；选中 ID 不完整、目标库/视图不存在或跨库不合法时整批拒绝，旧数据不改变。
- `POST /patents/bulk-move-database` 只改变 `Patent.database_id`，若原 `view_id` 属于旧库则同时清空 `view_id`；标签、项目、字段值和关系实体保留，并为数据库/视图变化写入 `PatentHistory(source=bulk)`。
- `POST /patents/bulk-move-view` 只允许移动到同一数据库的表格视图；`target_view_id=null` 表示回到库主表。不能把跨库视图 ID 写入专利。
- `POST /patents/bulk-duplicate` 的“复制”语义是创建可编辑工作副本，不是复制一篇正式专利。副本必须清空申请号、公开号、授权号和正式风险投影，保存 `duplicate_of`、来源说明、可继续加工的技术/自定义/AI 草稿；不能触发官方身份冲突。
- 批量编辑界面必须区分“预设高频字段”和“注册字段选择器”；风险正式投影、关系原始列、Link/Lookup/Rollup 和公式字段不能通过通用批量入口改写。空值表示“不修改”，不能被解释成清空。
- 批量标签必须明确 `追加`、`替换全部`、`移除` 三种模式，并显示目标专利数与标签数；未选择标签时不能提交。
- AI 批量操作必须是两步交互：先选范围（已选专利/当前页面等），再选一个 AI 输出字段，最后统一启动；列头快捷入口只能打开面板并预选字段，不能点击即发起网络任务。任务仍必须遵守 28 号契约并在任务列表可见。
- 导入历史时间线按 `import_batch_id` 聚合为默认折叠摘要；展开后才显示逐字段旧值、新值、来源行和来源列。聚合只是 UI 投影，不能删除或合并 `PatentHistory` 记录。
- 高频业务视图的产品/项目列必须使用已注册字段。`product_id` 在列表显示产品名称，`projects` 显示 `PatentProjectLink` 关系名称；二者不能以逗号文本写回主表，详情关系维护仍走项目关系 API。

## 7. 最终报告格式

Agent 完成任务时必须输出：

1. 结果：完成了什么，是否改变了当前产品行为；
2. 文档依据：读取和遵循了哪些文件/章节；
3. 文件改动：模型、服务、API、UI、测试、文档分别列出；
4. 验证：实际执行的命令和结果；
5. 未完成与风险：明确未实现、未验证和需要确认的事项。
